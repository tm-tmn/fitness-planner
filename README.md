# 🏋️ Fit & Meal Planner

เว็บแอป **ออกกำลังกาย** และ **อาหารการกิน** แบบหลายคนใช้ร่วมกัน (มีระบบสมัคร/ล็อกอิน แต่ละคนเห็นเฉพาะข้อมูลของตัวเอง) พร้อมปฏิทินดูภาพรวมทั้งเดือน, หน้าโปรไฟล์คำนวณเป้าแคลอรี่/โปรตีนอัตโนมัติ และ **"แผนเทรนเนอร์" 4 สัปดาห์** ที่กดปุ่มเดียวใส่ตารางออกกำลังกาย+อาหารทั้งเดือนให้เลย

สร้างด้วย **Next.js 14 (App Router) + TypeScript + Tailwind CSS** ฝั่งหน้าบ้าน และ **Supabase** (Postgres + Auth) เป็นฐานข้อมูล/ระบบล็อกอิน

พัฒนาโดย **Teerawat Maneewat**

---

## โครงสร้างหน้าเว็บ

| หน้า | path | ใช้ทำอะไร |
|---|---|---|
| เข้าสู่ระบบ/สมัคร | `/login` | สมัครสมาชิกด้วยอีเมล+รหัสผ่าน หรือเข้าสู่ระบบ |
| วันนี้ | `/` | ดู/เพิ่ม/ติ๊กเสร็จ มื้ออาหารและท่าออกกำลังกายของ "วันนี้" |
| ปฏิทิน | `/calendar` | ปฏิทินรายเดือน จุดเขียว = วันที่มีแผนแล้ว คลิกวันไหนก็ไปดู/แก้ไขได้ |
| รายวัน | `/day/2026-10-20` | รายละเอียดวันที่เลือก |
| โปรแกรม | `/program` | ดูภาพรวม "แผนเทรนเนอร์ 4 สัปดาห์" และกดเริ่มใส่ลงปฏิทิน |
| สถิติ | `/progress` | บันทึกน้ำหนัก ดูกราฟ สตรีคติ๊กครบติดกัน และป้ายรางวัล |
| โปรไฟล์ | `/profile` | ข้อมูลส่วนตัว + ปุ่มคำนวณเป้าแคลอรี่/โปรตีนอัตโนมัติ |

ทุกคนที่สมัครสมาชิกจะมีข้อมูลของตัวเอง แยกจากกันโดยสมบูรณ์ (Row Level Security ของ Supabase) — เพื่อนที่สมัครเข้ามาจะไม่เห็นตารางของคุณ และคุณจะไม่เห็นของเขา

## 1) ตั้งค่า Supabase

### ถ้าเป็นโปรเจกต์ Supabase ใหม่
1. ไปที่ https://supabase.com สร้างโปรเจกต์ใหม่
2. ไปที่ **SQL Editor** → วางเนื้อหาไฟล์ `supabase/schema.sql` ทั้งหมด → **Run**
3. ไปที่ **Authentication → Providers → Email** เปิดใช้งาน (เปิดอยู่แล้วโดย default)
4. (แนะนำสำหรับใช้กันในกลุ่มเพื่อน) ไปที่ **Authentication → Sign In / Providers → Email** แล้วปิด **"Confirm email"** เพื่อให้สมัครแล้วใช้งานได้ทันทีโดยไม่ต้องกดยืนยันในอีเมล — หรือถ้าเปิดไว้ก็ใช้ได้ปกติ แค่ต้องกดลิงก์ยืนยันในอีเมลก่อนครั้งแรก
5. ไปที่ **Project Settings → API** คัดลอก **Project URL** และ **anon public key**

### ถ้าเคยรันเวอร์ชันแรก (ไม่มี login) ไปแล้ว — ⚠️ สำคัญ
โปรเจกต์นี้เปลี่ยนโครงสร้างฐานข้อมูลเป็นแบบหลายผู้ใช้ ตารางเดิมใช้ร่วมกันไม่ได้แล้ว ให้:
1. เปิดไฟล์ `supabase/migration_v1_to_v2.sql` → รันใน SQL Editor (จะลบตารางเดิมทิ้ง)
2. ตามด้วยไฟล์ `supabase/schema.sql` (สร้างตารางเวอร์ชันใหม่)
3. ทำตามข้อ 3-5 ด้านบนด้วย

---

### อัปเดตเพิ่ม (v3): บันทึกน้ำหนัก
ถ้าเคยตั้งค่าไว้ก่อนหน้านี้ ให้เปิดไฟล์ `supabase/migration_v3_weight_logs.sql` แล้วรันใน SQL Editor หนึ่งครั้ง (สร้างตาราง `weight_logs` สำหรับหน้าสถิติ) — โปรเจกต์ใหม่ที่รัน `schema.sql` ไปแล้วไม่ต้องทำเพิ่ม

## 2) รันทดสอบในเครื่องตัวเอง (ไม่บังคับ)

```bash
npm install
cp .env.local.example .env.local
# แก้ไข .env.local ใส่ URL และ anon key จาก Supabase
npm run dev
```

เปิด http://localhost:3000 — ครั้งแรกจะเด้งไปหน้า `/login` ให้สมัครสมาชิก

## 3) อัปเดตโค้ดขึ้น GitHub (แทนที่ของเดิม)

โฟลเดอร์นี้คือโค้ดเวอร์ชันล่าสุดทั้งหมด (แก้ปัญหาโฟลเดอร์ซ้อนของเดิมด้วยแล้ว) วิธีอัปเดต:

```bash
# ไปที่โฟลเดอร์ repo ที่ clone ไว้ (หรือ clone ใหม่)
git clone https://github.com/tm-tmn/fitness-planner.git
cd fitness-planner

# ลบไฟล์เก่าทั้งหมด (เก็บ .git ไว้) แล้วคัดลอกไฟล์จากโฟลเดอร์นี้ทับเข้าไปแทน
# (ลาก-วางทุกไฟล์ในนี้ลงไปทับ ยกเว้นโฟลเดอร์ .git)

git add -A
git commit -m "Add multi-user auth, calorie calculator, 4-week trainer program"
git push
```

Vercel ที่เชื่อมกับ repo นี้ไว้แล้วจะ deploy เวอร์ชันใหม่ให้อัตโนมัติทันทีที่ push

> ไม่ต้องแก้ Environment Variables ใน Vercel — ยังใช้ `NEXT_PUBLIC_SUPABASE_URL` และ `NEXT_PUBLIC_SUPABASE_ANON_KEY` ชุดเดิม (แค่ต้องรัน SQL ใหม่ตามข้อ 1)

## 4) การใช้งาน "แผนเทรนเนอร์"

1. สมัครสมาชิก → ไปหน้า **โปรไฟล์** กรอกเพศ อายุ น้ำหนัก ส่วนสูง ระดับกิจกรรม แล้วกด **"คำนวณให้อัตโนมัติ"** เพื่อให้ระบบคำนวณเป้าแคลอรี่/โปรตีนที่เหมาะกับคุณ (หรือจะกรอกเองก็ได้) → กด **บันทึก**
2. ไปหน้า **โปรแกรม** → ดูภาพรวม 4 สัปดาห์ → เลือกวันเริ่ม (ค่าเริ่มต้นคือพรุ่งนี้) → กด **"เริ่มโปรแกรมนี้..."**
3. ระบบจะใส่ตารางออกกำลังกาย (3 วัน/สัปดาห์ บอดี้เวทล้วน ทำได้ทั้งบ้านและโรงแรม) และอาหารครบ 4 มื้อทุกวัน ลงในปฏิทินของคุณเอง โดยปรับแคลอรี่ตามเป้าที่คำนวณไว้
4. ไปหน้า **วันนี้** หรือ **ปฏิทิน** เพื่อติ๊กเช็คลิสต์รายวัน

เพื่อน/พี่/น้องที่อยากใช้ด้วย ให้เขาสมัครสมาชิกด้วยอีเมลของตัวเอง แล้วทำซ้ำข้อ 1-3 — แต่ละคนจะได้แผนที่ปรับตามข้อมูลร่างกายของตัวเอง และเห็นเฉพาะตารางของตัวเองเท่านั้น

> หมายเหตุ: ตัวเลขแคลอรี่ที่คำนวณให้เป็นค่าประมาณทั่วไปสำหรับคนทั่วไปที่ไม่มีโรคประจำตัว ไม่ใช่คำแนะนำทางการแพทย์ ถ้ามีภาวะสุขภาพเฉพาะทาง ควรปรึกษาแพทย์/นักโภชนาการก่อน

## 5) ประเมินแคลอรี่อัตโนมัติ + ให้ AI ประเมิน (ไม่บังคับ)

- ตอนเพิ่มมื้อ พิมพ์ชื่อเมนู (เช่น `ข้าวสวย + ไข่ดาว 2 ฟอง`) ระบบจะประเมินแคลอรี่จากคลังอาหารในแอปให้ทันที ใช้ได้ออฟไลน์ ไม่ต้องตั้งค่าอะไร และแก้ตัวเลขเองได้เสมอ
- ปุ่ม **"ให้ AI ประเมิน"** สำหรับเมนูที่คลังไม่รู้จัก ต้องตั้ง Environment Variable ใน Vercel อย่างใดอย่างหนึ่ง (ถ้าตั้งทั้งคู่ ใช้ Gemini):
  - `GEMINI_API_KEY` = คีย์จาก aistudio.google.com (มีแพ็กเกจฟรี แต่ Google อาจนำข้อความไปพัฒนาผลิตภัณฑ์ — แอปส่งเฉพาะชื่ออาหาร ไม่ส่งข้อมูลส่วนตัว) ไม่บังคับ: `GEMINI_MODEL` (ค่าเริ่มต้น `gemini-3.1-flash-lite`)
  - หรือ `ANTHROPIC_API_KEY` = คีย์จาก console.anthropic.com (คิดเงินตามการใช้งาน) ไม่บังคับ: `ANTHROPIC_MODEL` (ค่าเริ่มต้น `claude-haiku-5-5`)
  - ถ้าไม่ตั้งคีย์เลย ปุ่มจะแจ้งว่ายังไม่เปิดใช้ แล้วให้ใส่แคลอรี่เอง
- ต้องล็อกอินจึงเรียกได้ และจำกัดข้อความไม่เกิน 200 ตัวอักษรต่อครั้ง
- ปุ่ม **"ถ่ายรูปให้ AI ประเมิน"**: เลือกหรือถ่ายรูปอาหาร หน้าเว็บย่อรูปเหลือด้านยาวสุด 800px (ตัดข้อมูลตำแหน่งในรูปออก) แล้วส่งให้ AI ประเมินชื่อเมนูกับแคลอรี่ ไม่เก็บรูปในแอป ครั้งแรกจะมีข้อความยืนยันก่อนส่ง ใช้คีย์เดียวกับด้านบน
- **กินบ่อย**: ปุ่มลัดของอาหารที่ติ๊กกินจริงใน 60 วันล่าสุด แยกตามมื้อ กดแล้วเพิ่มทันที และปุ่ม **ก๊อปมื้อเมื่อวาน** คัดลอกรายการของเมื่อวานมาวันนี้ (ข้ามรายการที่มีอยู่แล้ว)
- **สรุปสัปดาห์** (หน้าสถิติ): ตัวเลข 7 วันล่าสุดพร้อมเคล็ดลับจากกฎในแอป และปุ่ม "ให้โค้ช AI เขียนให้" (`/api/coach`) ซึ่งส่งให้ AI เฉพาะตัวเลขสรุป ไม่ส่งชื่ออาหาร
- **โปรตีนในสรุปรายวัน**: ประเมินจากชื่อเมนูด้วยคลังในแอป (ไม่ต้องแก้ฐานข้อมูล ไม่ส่งไปที่ไหน) แล้วสเกลตามแคลอรี่ที่บันทึกไว้ แสดงโปรตีนที่ติ๊กกินแล้ว เทียบแผนทั้งวันและเป้าในโปรไฟล์ เมนูที่คลังไม่รู้จัก (เช่น ที่ AI ประเมินแคลอรี่ให้) จะไม่นับและแจ้งจำนวนไว้
- **แนวโน้มน้ำหนัก** (หน้าสถิติ): คำนวณเส้นแนวโน้มจากน้ำหนักที่บันทึกตั้งแต่แก้เป้าครั้งล่าสุด (ไม่เกิน 28 วัน ต้องมีอย่างน้อย 3 ครั้งครอบคลุม 10 วัน) เทียบกับการลดช้าๆ ~0.5% ของน้ำหนักตัวต่อสัปดาห์ แล้วแนะนำปรับเป้าแคลอรี่ครั้งละไม่เกิน 200 kcal ไม่ต่ำกว่า 1,500 (ชาย) / 1,200 (หญิง) ผู้ใช้ต้องกดยืนยันเอง ไม่ปรับเงียบๆ
- **โปรตีนเฉลี่ยในสรุปสัปดาห์**: แสดงโปรตีนเฉลี่ยต่อวันและจำนวนวันที่ถึงเป้า (ประเมินจากชื่อเมนูเหมือนสรุปรายวัน) และส่งตัวเลขนี้ให้โค้ช AI ด้วย
- **รายการซื้อของ** (`/shopping` ลิงก์อยู่ที่หัวข้อมื้ออาหารในหน้าวันนี้): รวมวัตถุดิบหลักจากมื้อที่ยังไม่ติ๊กใน 3 หรือ 7 วันข้างหน้า แยกหมวด ติ๊กของที่ซื้อแล้วได้ (จำไว้ในเบราว์เซอร์เครื่องนั้น) และคัดลอก/แชร์เป็นข้อความ แยกวัตถุดิบด้วยคำสำคัญในแอป เมนูที่แยกไม่ได้จะอยู่หมวด "เมนูที่ต้องดูเอง"
- AI ทุกปุ่มจำกัดการเรียกต่อผู้ใช้ (ข้อความ 40 ครั้ง/รูป 20 ครั้งต่อ 10 นาที, โค้ช 8 ครั้งต่อชั่วโมง) นับแยกตาม instance ของเซิร์ฟเวอร์ จึงเป็นแค่เบรกกันกดรัว

## เทคโนโลยีที่ใช้

- [Next.js 14](https://nextjs.org/) (App Router, TypeScript)
- [Tailwind CSS](https://tailwindcss.com/)
- [Supabase](https://supabase.com/) — Postgres + Auth (`@supabase/ssr` สำหรับ session แบบ cookie บน Next.js)
- [date-fns](https://date-fns.org/) สำหรับคำนวณปฏิทิน
- Deploy บน [Vercel](https://vercel.com/)
